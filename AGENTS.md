# EasyKind - Agent Guide

## What this repo is
Bash scripts to set up a Kind (Kubernetes-in-Docker) cluster on Linux with Docker, kind, kubectl, Helm, Calico CNI, kube-vip bootstrap, optional Envoy Gateway, Argo CD, and a GitOps repository connection. Envoy Gateway can be managed by EasyKind or Argo CD; choose one owner. Designed to be installed via `bootstrap.sh` and run with `main`.

## Install / entrypoints
- Bootstrap: `./bootstrap.sh` (requires sudo; installs Go/gum, sets inotify limits, copies scripts to `/usr/local/bin` and assets to `/usr/local/share/easykind`, adds Go bin to PATH in `~/.bashrc`).
- CLI menu: `main` (installed to PATH). Sources `scripts/common`, `install_binaries`, `create_cluster`, `install_calico`, `kube_vip`, `install_envoy_gateway`, `install_argocd`, `configure_gitops`, `install_etcdctl`, `upgrade_cluster`, `delete_cluster`, `cleanup`. Requires `gum`. Shows menu: Install binaries → Create cluster → Install Calico → Install kube-vip → Install Envoy Gateway → Install Argo CD → Configure GitOps → Install etcdctl → Upgrade cluster → Delete cluster → Cleanup → Exit.
- Templates: `script_template` shows pattern (source `common`, define function, run if executed directly).

## Commands (exact)
**From repo root (dev):** scripts can be run directly if dependencies present. Each script supports being sourced or executed directly (checks `BASH_SOURCE[0] == "$0"`).
- `./scripts/install_binaries` - installs docker (via get.docker.com), kind via `go install sigs.k8s.io/kind@v0.33.0` (needs Go), kubectl (downloads latest stable from dl.k8s.io for detected arch), helm (via get-helm-3 script), adds `alias k='kubectl'` to `~/.bashrc`.
- `./scripts/create_cluster` - prompts for cluster name; if exists, returns early. Looks for cluster config via `cluster_config_path()`: checks `KIND_CLUSTER_CONFIG` env var first, then `scripts/../assets/config-cluster.yaml`, then `/usr/local/share/easykind/assets/config-cluster.yaml`. Prompts for the Kubernetes (`kindest/node`) version via `request_version`; blank uses `KIND_KUBERNETES_VERSION` (default `v1.37.0`), and a leading `v` is added if missing. Prompts to retain failed nodes (`--retain`). Runs `kind create cluster --name ... --config ... --image kindest/node:<version> [--retain]`. The included config disables the default CNI and sets `podSubnet: 192.168.0.0/16` for Calico.
- `./scripts/install_calico` - prompts for cluster name (must exist). Refuses to run if kindnet is still present or if Calico is already installed. Gets latest Calico release from GitHub API (or `CALICO_VERSION`) and prompts for the version via `request_version` (blank uses that latest/override). Applies `https://raw.githubusercontent.com/projectcalico/calico/${version}/manifests/calico.yaml`, waits for `calico-node` and `calico-kube-controllers`, then waits for all nodes to be Ready. Calico uses its default pod CIDR `192.168.0.0/16`, which must match the kind `podSubnet`.
- `./scripts/kube_vip` - prompts for cluster name (must exist). Gets latest kube-vip release from GitHub API (or `KUBE_VIP_VERSION`) and prompts for the version via `request_version` (blank uses that latest/override). Determines LoadBalancer range from `docker network inspect kind` (16-bit -> `a.b.100.10-a.b.100.30`, 24-bit -> `a.b.c.100-a.b.c.130`); else prompts. Installs cloud controller, creates ConfigMap `kubevip` in `kube-system` with `range-global`, applies RBAC, deploys daemonset via `docker run ghcr.io/kube-vip/kube-vip:${kv_version} manifest daemonset --services --inCluster --arp --interface eth0`, waits for rollout.
- `./scripts/install_envoy_gateway` - prompts for cluster name and Envoy Gateway version, installs the `gateway-helm` OCI chart as release `eg`, waits for the controller, and creates GatewayClass `eg`. Use either this script or Argo CD to manage the release, not both.
- `./scripts/install_argocd` - prompts for cluster name (must exist) and Argo CD version via `request_version` (default latest GitHub release from `argoproj/argo-cd`, or `ARGOCD_VERSION`; a leading `v` is added when the input starts with a digit). Creates the `argocd` namespace, applies `https://raw.githubusercontent.com/argoproj/argo-cd/<version>/manifests/install.yaml` with `kubectl apply --server-side --force-conflicts` (the CRDs are too large for client-side apply annotations), waits for all Deployments to be Available and the `argocd-application-controller` StatefulSet to roll out, then prints the UI port-forward and initial admin password retrieval commands. Uses `kubectl --context kind-<cluster_name>`.
- `./scripts/configure_gitops` - requires `gum`, a Kind cluster and Argo CD. Prompts for the repository URL, branch, authentication and path. The path defaults to `.`; `GITOPS_REPO_PATH` overrides it. Creates the Argo CD repository Secret and root Application with automated sync, `prune: false` and `selfHeal: true`. Argo manages workloads and post-bootstrap add-ons declared in the repository. EasyKind retains cluster creation, Calico and kube-vip bootstrap, initial Argo CD installation, node tools, upgrades and etcd restore.
- `./scripts/install_etcdctl` - prompts for cluster name (must exist). Gets latest etcd release from GitHub API (or `ETCDCTL_VERSION`) and prompts for the version via `request_version` (blank uses that latest/override). Downloads tarball for detected arch, extracts `etcdctl` (and `etcdutl` via `install_etcdutl`), copies to `/usr/local/bin/etcdctl` and `/usr/local/bin/etcdutl` on each control-plane node via `docker cp` and `docker exec chmod +x`.
- `./scripts/upgrade_cluster` - prompts for cluster name (must exist) and target Kubernetes version via `request_version` (default latest patch of the next minor from `dl.k8s.io`, or `KIND_KUBERNETES_UPGRADE_VERSION`). Rejects downgrades and skipped minors; allows same-minor patch upgrades. Reads the current version from `kubectl get --raw /version`, determines control-plane/worker nodes from `kubectl get nodes`, downloads and SHA-256-verifies `kubeadm`, `kubelet` and `kubectl` for the detected arch, copies them into node containers, then runs `kubeadm upgrade apply` on the first control-plane, `kubeadm upgrade node` on the remaining control-planes and workers, restarts kubelet, and waits for each node to report the target kubelet version. Uses `--ignore-preflight-errors=SystemVerification` for kind. Does not drain a single worker; drains/uncordons workers only when there is more than one. Verifies kube-proxy and Calico rollouts when present.
- `./scripts/delete_cluster` - prompts for name with retry if not found; confirms before `kind delete cluster`.
- `./scripts/cleanup` - prompts to remove installed scripts (`main,install_binaries,create_cluster,install_calico,kube_vip,install_envoy_gateway,install_argocd,configure_gitops,install_etcdctl,upgrade_cluster,delete_cluster,cleanup,common`) from `/usr/local/bin` and assets from `/usr/local/share/easykind`.

## Gotchas / repo-specific facts
- `bootstrap.sh` removes legacy `${BIN_DIR}/install` if present (conflicts with system install). Copies all files from `scripts/*` (only files) to `/usr/local/bin` with +x. Copies all files from `assets/*` to `${SHARE_DIR}/assets/`.
- `main` requires `gum` installed; exits if missing. Sources scripts in order.
- `install_binaries` adds `export PATH="$(go env GOPATH)/bin:${PATH}"` if go present; `main` also does this. Adds `alias k='kubectl'` to `~/.bashrc` and sources it.
- `create_cluster` will not recreate an existing cluster (just logs and returns). The config is in `assets/config-cluster.yaml`; it must keep `disableDefaultCNI: true` and `podSubnet: 192.168.0.0/16` for Calico.
- `install_calico` will not install on a cluster still running kindnet; the cluster must be recreated from the updated config. It also returns early if `calico-node` already exists.
- `kube_vip` uses `docker network inspect kind` to infer range; requires docker running and kind network existing. Deploys with `--interface eth0` (hardcoded). Uses `kubectl --context kind-${cluster_name}`.
- `install_envoy_gateway` installs Envoy Gateway directly. A connected GitOps repository may install it declaratively instead; do not leave both managers targeting the same Helm release or GatewayClass.
- `install_argocd` uses the upstream install manifest, not Helm. It must use server-side apply because the `applicationsets.argoproj.io` CRD exceeds the 262144-byte annotation limit of client-side apply. The `argocd-server` Service is ClusterIP, so the UI is reached through `kubectl port-forward svc/argocd-server 8080:443` unless the user exposes it separately. It prints the command to read `argocd-initial-admin-secret` instead of printing the secret itself. Re-running it applies the manifest again, which can be used to finish a partial install or change the Argo CD version.
- `configure_gitops` deliberately leaves cluster creation, Calico, kube-vip bootstrap, initial Argo CD installation, node binaries, Kubernetes upgrades and etcd restore in the bootstrap/manual layer. It creates the root Argo CD Application; after that, GitOps owns post-bootstrap add-ons declared in the repository. Envoy Gateway may be installed by EasyKind or Argo CD, but only one should own its Helm release and GatewayClass. The path defaults to the repository root (`.`), and `GITOPS_REPO_PATH` can override it. The path is normalized, must not contain `..`, and the Application name is derived from the repo name plus the path basename to avoid collisions with child Applications. Because `prune: false` is set for this root Application, Argo updates existing objects but does not delete objects missing from Git. The repo URL has no default. Private HTTPS uses the Argo CD repository Secret `username`/`password` fields; private SSH uses `sshPrivateKey`. Do not add `sshKnownHosts` to the repository Secret for core Argo CD; host keys belong in `argocd-ssh-known-hosts-cm` (GitHub/GitLab defaults are built in). Repository Secret values are base64-encoded under `data`, so tokens and keys are not interpolated into YAML.
- `upgrade_cluster` is an in-place kind upgrade, not the usual kind recreate-with-new-node-image path. It replaces `/usr/bin/kubeadm`, `/usr/bin/kubelet` and `/usr/bin/kubectl` inside the node containers using `docker cp` to a `.new` file followed by `mv`, so a running kubelet is not overwritten while executing. It must pass `--ignore-preflight-errors=SystemVerification` because node containers cannot load the VM kernel's `configs` module. The `dl.k8s.io` `.sha256` files contain only the hash, so it compares hashes instead of using `sha256sum -c`.
- Logging via `log_info/warn/error` from `common` with timestamps/colors.
- All scripts use `set -euo pipefail`. When sourced, they define functions; when executed directly, they source `common` and run the main function.

## Conventions
- Scripts are modular: shared helpers in `common`. Follow `script_template` pattern for new scripts (define function, guard for direct execution).
- Prefer using `request_user_input` from `common` for prompts requiring non-empty input.
- Prefer using `request_version` from `common` for version prompts: it shows the default in brackets and returns it when the user presses Enter.
- No tests, linters, formatters, CI, or package manifests present.
